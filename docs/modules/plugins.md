# Plugins (ихтиёрий фичалар реестри) - SPEC

Ҳолат: **ТАСДИҚЛАНГАН** (фойдаланувчи дизайнни 2026-07-12 да келишди;
карта: Arbitr-113). Талаб: Созламада Plugins бўлими, плагин toggle-on
қилинса ўз созламаси/менюси пайдо бўлади; келажакда плагин қўшиб
борилади.

## Тушунча ва чегара (МУҲИМ - over-engineering ЭМАС)

- **Plugin = built-in ихтиёрий фича** (масалан Telegram). Код ичида
  олдиндан белгиланган (curated ENUM) - фойдаланувчи код юкламайди.
- **Динамик plugin loader/marketplace ЙЎҚ** (хавфсизлик + соддалик):
  бу оғир тизим эмас, енгил **фича-флаг реестри** + Созлама UI.
- Ҳар плагин: калит, ном, тавсиф, ихтиёрий созлама йўли, ёқилиш ҳолати.
- SUPER_ADMIN ёқади/ўчиради; ёқилса плагиннинг менюси/созламаси/хулқи
  пайдо бўлади, ўчса яширин.

## Кўлам

1. **Реестр** (код): `PluginKey` enum - ҳозир `TELEGRAM` (биринчи).
   Ҳар калитда метамаълумот: ном/тавсиф message калити, созлама
   route (ихтиёрий). Янги плагин = янги enum + код (схема ўзгармайди).
2. **plugin_state жадвали** (changeset 065): plugin_key (PK varchar),
   enabled (bool default false), updated_at, updated_by. Битта қатор/
   плагин; йўқ бўлса default ўчиқ.
3. **Созлама → Plugins саҳифаси** (`/settings/plugins`, SUPER_ADMIN):
   ҳар плагин - ном, тавсиф, **toggle** (ёқ/ўчир). Ёқилганда плагин
   созламасига ҳавола («Созлаш →»). Toggle → plugin_state ёзилади +
   аудит (PLUGIN_TOGGLED ёки мавжуд нақш).
4. **Гейт helper**: `PluginService.isEnabled(PluginKey.X)` (енгил
   сўров/кэш). Ишлатилади:
   - **Меню** (main.jte): плагин меню бандлари фақат enabled'да;
   - **Созлама**: плагиннинг созлама бўлими/ҳаволаси фақат enabled'да
     (масалан Telegram token асосий Созламада enabled бўлса чиқади);
   - **Фича коди**: масалан Telegram poller ФАҚАТ TELEGRAM enabled'да
     ишлайди.
5. **Telegram = биринчи плагин** (103): TELEGRAM enabled бўлса →
   `/settings/telegram` (токен) асосий Созламада пайдо + профил улаш
   блоки + poller. Ўчиқ → ҳаммаси яширин, poller тўхтайди. Токен
   telegram_settings'да (плагин-хос), ЁҚИЛИШ ҲОЛАТИ plugin_state'да.

## Дизайн қарорлари

- Реестр enum (curated) - хавфсиз (ихтиёрий код йўқ, инъекция юзаси
  йўқ). Плагин қўшиш = арбитр/coder иши, фойдаланувчи эмас.
- plugin_state - жадвал (CompanySettings'даги boolean майдонлар эмас): янги
  плагин схема ўзгартирмайди, фақат enum + код.
- Гейт helper марказий (Perms.current() нақши - layout + controller +
  фича бир хил манбадан).
- Ўчирилган плагин маълумоти ЎЧМАЙДИ (Telegram токени сақланади,
  фақат яширин + poller тўхтайди) - қайта ёқса тикланади.

## Экранлар (JTE)

- `/settings/plugins` - плагинлар рўйхати + toggle + «Созлаш →»
  ҳаволаси (enabled'да). helpKey. SUPER_ADMIN.
- Асосий Созламадан «Plugins →» ҳавола.
- Мобил 375px.

## BR / хавфсизлик

- Toggle фақат SUPER_ADMIN (092; UrlPermissionMap `/settings/plugins`
  settings соҳаси остида); паст роль 403.
- Аудит: плагин ёқилди/ўчирилди (ким, қачон).
- Плагин enabled бўлмаса унинг ҳеч бир route/меню/фичаси
  ишламайди (гейт helper ҳар нуқтада - «яширин UI + гейтли backend»,
  092 нақши: UI яширгани кифоя эмас, backend ҳам текширади).

## Тестлар (минимум)

plugin_state CRUD + toggle; isEnabled гейт (enabled/disabled);
SUPER_ADMIN toggle, паст роль 403; enabled'да меню/созлама кўриниши,
ўчиқда яширин + backend route гейти (disabled Telegram poller
ишламайди/route 403); аудит ёзуви; мавжуд SettingsWebTest яшил;
changeset dev boot validate; 375px.

## Кенгайтириш стратегияси (қарор 2026-07-12)

Фойдаланувчи билан муҳокама - келажак плагинлар қандай қўшилади:
- **Built-in модул toggle (ҲОЗИРГИ механизм)**: биз ёзган фичалар
  реестрга enum сифатида қўшилади, runtime'да toggle. Мисоллар:
  `TELEGRAM` (биринчи), келажакда **`POS`** (built-in модул),
  бошқа интеграциялар. Хавфсиз, арзон - 95% эҳтиёжни қоплайди.
- **Динамик third-party JAR (PF4J/OSGi) - РАД** (молиявий ERP):
  ихтиёрий кодни ledger ҳуқуқи билан ишга тушириш - хавфсизлик/
  яхлитлик риски (темир қоидалар, JTE precompile, changeset реестри,
  review дарвозаси бузилади). QBO/Xero ҳам in-process код плагин
  қилмайди.
- **Учинчи-тараф кенгайтириш йўли = API + OAuth** (QBO App
  Marketplace усули): ташқи илова HTTP орқали гаплашади (sandboxed,
  ledger'га тўғридан тегмайди). **Бу API+OAuth ИМКОНИ ҲАМ ПЛАГИН
  бўлади** (`PluginKey.API` ёки `EXTERNAL_API`): default ЎЧИҚ,
  SUPER_ADMIN toggle-on қилса оммавий API endpoint'лари + OAuth
  илова рўйхатга олиш пайдо бўлади; off → ташқи API юзаси йўқ.
  Изчил: ташқи интеграция ҳам худди Telegram каби ихтиёрий, гейтли.
- **Агар in-process модуллик керак бўлса** (мас. POS'ни алоҳида JAR):
  фақат ЎЗИМИЗ ёзган ишончли модул, PF4J мумкин - лекин compile-time
  модул + runtime toggle (ҳозирги нақш) соддароқ/хавфсизроқ, натижа
  бир хил. YAGNI: ҳозир қурилмайди.

## 2-босқич (ҳозир ЭМАС)

Плагинга боғлиқлик/тартиб (плагин X плагин Y'ни талаб қилса);
плагин конфиг схемаси умумийлаштириш; роль-даража плагин кўриниши
(ҳозир SUPER_ADMIN-only бошқарув); API+OAuth плагини (юқорида);
POS built-in плагини.
