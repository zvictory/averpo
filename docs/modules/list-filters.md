# Рўйхат филтрлари - SPEC

## Мақсад

Ҳар рўйхат экранида фойдаланувчи ичидаги ёзувларни ФИЛТРЛАБ олиши
керак: давр, статус, контакт, матн қидируви - саҳифадан чиқмасдан.
Фойдаланувчи талаби: «кўп page'ларда мукаммал filter
йўқ». Эталон: QBO рўйхатлари (filter қатори: Status / Date / Customer
+ matn) - ҳамма жадвал устида бир хил услуб.

Жорий ҳолат (кўрик натижаси): бир қисм рўйхатда GET
филтр БОР (bills, invoices, estimates, purchaseOrders,
journalEntries, movements, balances, item/list, accountTransactions,
auditLog - НАҚШ сифатида ишлатилсин), лекин тўплами ҳар хил; бошқа
рўйхатларда умуман йўқ (payments, creditMemos, vendorCredits,
salesReceipts, refundReceipts, transfers, bank txn, contacts,
warehouses, payroll runs, employees, landedCosts...).

## Стандарт (қайси рўйхатга нима)

**Ҳужжат рўйхатлари** (invoices, bills, salesReceipts, creditMemos,
vendorCredits, refundReceipts, estimates, purchaseOrders, payments
(икки томон), transfers, bank транзакциялар, journalEntries,
landedCosts, payroll runs):

- Давр: from/to сана (бўш = чекланмаган);
- Статус: ҳужжатнинг ўз статуслари бўйича select (бор бўлса);
- Контакт: мижоз/таъминотчи select (тегишли ҳужжатларда) -
  combobox.md қоидаси билан (қидирувли);
- Матн: ҳужжат рақами/изоҳ бўйича contains қидирув.

**Каталог рўйхатлари** (contacts, items, accounts, warehouses,
employees):

- Матн: ном/код contains;
- Фаоллик: фаол/нофаол/ҳаммаси (default: фаол);
- Тур/категория: бор бўлса (контакт тури, товар тури/категорияси,
  счёт classification).

Ҳисоботлар (TB/BS/P&L/aging/register...) бу spec'га КИРМАЙДИ -
уларда ўз давр бошқаруви бор.

## Дизайн қарорлари

- Механика: ОДДИЙ GET форма (bookmark қилинади, back тугмаси
  ишлайди) - audit-log экрани НАҚШ (from/to/type/username + Pageable).
  HTMX шарт эмас - мураккаблаштирилмайди.
- Pagination билан ҳамкорлик: филтр ўзгарганда page=0 га қайтади;
  саҳифалаш линклари филтр параметрларини САҚЛАЙДИ (PERF-perf1
  pagination master'ига мос).
- Repo қатлами: ҳар модул ЎЗ query методини беради (қоида 6) -
  audit filter услубига эргашилади; умумий framework/Specification
  мажбурланмайди.
- Матн қидируви case-insensitive (кирилл ҳам!) - PostgreSQL ILIKE;
  тестда кирилл катта-кичик ҳарф текшируви МАЖБУРИЙ.
- UI: жадвал устида битта филтр қатори (мобил 375px'да wrap),
  «Филтрлаш» submit + «Тозалаш» линки (параметрсиз шу саҳифа).
  Бўш натижа - мавжуд empty-state услуби.
- Default'лар: давр бўш (ҳаммаси), каталогда фаоллик=фаол.
- Саралаш (column sort) - 2-БОСҚИЧ: MVP'да мавжуд тартиб (янгидан
  эскига) қолади.
- Changeset КЕРАК ЭМАС (индекслар етарли - created_at/док сана
  индекслари бор; секинлик кўрилса алоҳида карта).

## Бажариш тартиби

1. Gap-аудит: ҳар рўйхат экрани бўйича «бор/йўқ/чала» жадвали
   (журналга) - юқоридаги съёмка асос.
2. Модулма-модул қўшиш: sales → purchase → bank/ledger → inventory →
   каталоглар → payroll (ҳар модул алоҳида тест билан).
3. i18n калитлар уч тилда; мавжуд филтрли экранлар стандартга
   мосланади (масалан статус йўқ бўлса қўшилади), бузилмайди.

## Тестлар (мажбурий рўйхат)

1. Ҳар қўшилган филтр учун web тест: параметр берилганда рўйхат
   тўғри кесилади (камида давр + статус + матн ҳар модулда).
2. Кирилл матн қидируви case-insensitive (масалан «синов» / «Синов»).
3. Pagination + филтр биргаликда: 2-саҳифада филтр сақланади.
4. Филтрсиз default'лар аввалги хатти-ҳаракат билан бир хил
   (regression - мавжуд ScreenSmoke яшил).
