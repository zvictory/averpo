# Global Search - Глобал қидирув (QBO Navigate паритети) - SPEC

ҲОЛАТ: БАЖАРИЛДИ 2026-07-09 (Arbitr-039); 061 да қидирув сайдбарга
кўчди, 074 да қамров кенгайди (тўловлар/банк txn/landed cost).

## Мақсад

QBO топбаридаги «Navigate. Find transactions, contacts, help,
reports...» қидируви паритети: битта майдондан ҳужжат рақами,
контакт, товар, счёт ва экран/ҳисобот номи бўйича бутун тизимни
қидириш ва бир босишда ўтиш.

## Кўлам (MVP - 1.0 учун)

Қидирилади (натижа гуруҳлари, ҳар гуруҳда кўпи билан 5 та):

1. **Ҳужжатлар** - рақам бўйича (substring, регистрсиз): invoice,
   bill, credit memo, vendor credit, refund receipt, sales receipt,
   estimate, PO, JE, мижоз тўлови (RCPT-), таъминотчига тўлов (PAY-),
   банк транзакциялари (BT-; ref_no бўйича ҳам - Ulugbek-016), landed
   cost тақсимоти (LC-), payroll ҳужжатлари (PAYR-/PAYP-). Рўйхат
   кодда битта жойда - GlobalSearchService.DOC_SOURCES (Arbitr-074:
   тўловлар/банк txn/landed cost қўшилган - QBO Navigate паритети).
   Натижа: рақам + контакт номи + сана + сумма → кўриш экранига линк.
2. **Контактлар** - ном/компания бўйича (ILIKE %q%): мижоз/
   таъминотчи/ходим → карточка/таҳрирга линк.
3. **Товарлар** - ном/SKU бўйича → item таҳрирга линк.
4. **Счётлар** - ном/код бўйича → Account history'га линк.
5. **Экранлар/ҳисоботлар** - статик реестр (сайдбар бандлари ва
   ҳисоботлар: номи + route), жорий тил бўйича филтр - «баланс» деб
   ёзса Balance Sheet чиқади. Роль филтри (VIEWER_AUDITOR
   кўрмайдиганлари чиқмайди).

ҚИЛИНМАЙДИ (MVP'дан ташқари, триггер: реал ҳажмда секинлашув ёки
фойдаланувчи сўрови): memo/изоҳ ичида full-text, pg_trgm/tsvector
индекслари, охирги қидирувлар тарихи, fuzzy typo-tolerance.

## Архитектура

- Янги `search` модули: `GlobalSearchService.search(rawQuery, isAdmin)`
  (Ulugbek-025: имзо ҳақиқатга мосланди - limit параметр эмас, ичкарида
  GROUP_LIMIT=5 константа; isAdmin экран реестрининг роль филтри учун) -
  JdbcClient билан ҳар манбага биттадан енгил SELECT (id, номи,
  қўшимча устун, route учун маълумот). Бошқа модуллар repo'сига
  тегилмайди - dashboard/LedgerDashboardService хом SQL прецеденти
  (read-only). Ҳар SELECT'да LIMIT 5, умумий жавоб DTO рўйхати.
- Query нормализацияси: trim, минимал узунлик 2 белги; ILIKE
  %query% (регистрсиз, кирилл/лотин қандай ёзилса шундай қидирилади).
- Экран реестри: enum/рўйхат кодда (route + message калити + роль) -
  сайдбар билан бир манбадан адашмаслиги учун изоҳда сайдбарга
  ҳавола.
- Хавфсизлик: barcha натижалар мавжуд рўйхат экранлари кўрсатадиган
  маълумот (қўшимча ҳуқуқ текшируви фақат экран реестрида - роль).
  SQL параметр binding (инъекция йўқ), янги BR код керак эмас
  (read-only).

## UI

- Сайдбарда қидирув майдони (061 қарори, Б вариант - QBO'дагидек
  топбарда эмас): placeholder «Қидирув: ҳужжат, контакт, товар...»
  (уч тилда). Мобил 375px: сайдбарда лупа иконкаси - босилса майдон
  тўлиқ кенгликда очилади.
- HTMX: keyup (debounce 300ms, min 2 белги) → GET /search?q= →
  dropdown partial (гуруҳланган натижалар, ҳар сатр линк).
- Клавиатура: «/» босилса майдонга фокус (input ичида бўлмаса);
  ↑/↓ натижалар бўйлаб, Enter очади, Esc ёпади (Alpine).
- Натижа йўқ бўлса «Ҳеч нарса топилмади» + маслаҳат сатри.
- JS'сиз fallback: Enter босилса /search саҳифаси тўлиқ очилади
  (ўша натижалар оддий саҳифада).

## Тестлар (мажбурий рўйхат)

1. Ҳужжат рақами бўйича топилади (камида invoice/bill/JE) - тўғри
   route билан; қисман рақам ҳам (substring).
2. Контакт/товар/счёт номи бўйича ILIKE регистрсиз топилади.
3. Ҳар гуруҳда LIMIT 5 ишлайди (6 та мос ёзувда 5 қайтади).
4. 2 белгидан қисқа query - бўш натижа (сўров юборилмайди).
5. Экран реестри роль бўйича филтрланади (VIEWER_AUDITOR'га Settings
   экранлари чиқмайди).
6. /search тўлиқ саҳифа смоки + dropdown partial смоки (HX-Request).

## Туртки режаси

Битта туртки (D-тўлқинда бажарилган): search модули + сайдбар UI +
/search саҳифаси + тестлар. Changeset КЕРАК ЭМАС (схема ўзгармайди).
