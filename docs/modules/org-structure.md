# Ташкилий тузилма (org structure) - SPEC

Ҳолат: **ТАСДИҚ КУТМОҚДА** (қарорлар фойдаланувчи билан келишилган Q&A; спец  (UX/BA) кўригидан кейин карта).

Манба: фойдаланувчи талаби: ERP'да ташкилий тузилма
қуриш имкони, бир нечта хил тузилма бир вақтда, жуда мослашувчан.

## QBO ва онгли фарқ

QBO'да org-структура/org-chart тушунчаси **ЙЎҚ** - у фақат Class ва
Location тег беради. Бу модул QBO'дан ташқари - **онгли фарқ**
(multi-warehouse, Payroll Lite прецеденти; фойдаланувчи
қарори). Техник негиз мавжуд **TxnClass** нақши (иерархик дарахт,
parent, чексиз чуқурлик) - исботланган.

## Кўлам (ҲОЗИРГИ, содда MVP)

Фойдаланувчи қарори: ҳозирча ФАҚАТ **кўриш/бошқариш** - ходимлар ва
тузилмани кўриш. Транзаксияга тег ва кириш назорати ҲОЗИР ЭМАС -
кейин, худди Class қўшилгани каби, босқичма-босқич қўшилади.

1. **Бир нечта тузилма** - ҳар бири ўз ТУРИ билан, бир вақтда фаол.
2. **Ҳар тузилма - unit'лар дарахти** (мустақил); unit = Branch/
   Department/Дивизион... (ном тузилма/даражага қараб).
3. **Ходим** (Contact type=EMPLOYEE) unit'ларга жойланади: ҳар
   тузилмада БИТТА unit, барча тузилмада қатнаша олади (мас.
   функционалда «Сотув», географикда «Тошкент» бир пайтда).
4. **Фақат аъзолик** - раҳбар/бўйсуниш чизиқлари ЙЎҚ (2-босқич).

## Маълумот модели (changeset 063)

- **org_structure**: id, name, type (enum, қуйида), active,
  sort_order. Бир нечта бўлади.
- **org_unit**: id, structure_id (FK), name, code (ихтиёрий),
  parent_id (self-ref nullable - дарахт, TxnClass нақши), active.
  Ҳар unit БИТТА тузилмага тегишли (тузилмалар unit'ни бўлишмайди).
- **org_unit_member** (боғ): id, employee_contact_id (FK contact),
  org_unit_id (FK org_unit), structure_id (денормаллашган - қуйидаги
  UNIQUE учун). UNIQUE(employee_contact_id, structure_id) - битта
  ходим бир тузилмада фақат битта unit'да (4-банд); лекин ҳар
  тузилмада алоҳида ёзув (3-банд). Ходим ўчса каскад.

**OrgStructureType enum** (тур = MVP'да ЁРЛИҚ, дарахт шаклини
чекламайди - маъно фарқи): FUNCTIONAL (функционал), DIVISIONAL
(дивизионал), GEOGRAPHIC (географик), PRODUCT (маҳсулотга асосланган),
PROCESS (жараёнга асосланган), MATRIX (матрица/бошқарув), PROJECT
(лойиҳага асосланган), HOLDING (холдинг), LINEAR (иерархик/чизиқли).
Кенгайтириш осон (enum + messages).

ТЕГИЛМАЙДИ (фойдаланувчи «ҳозирча боғламай тур»): unit ↔ warehouse
боғланиши; unit ↔ GL/class; кириш назорати - барчаси 2-босқич.

## Экранлар (JTE + HTMX, mobile-first)

- **/org** - тузилмалар рўйхати (ном, тур, unit сони, ходим сони) +
  «Янги тузилма». helpKey (доимий қоида).
- **/org/{id}** - битта тузилма кўриниши: unit дарахти (indent/
  accordion), ҳар unit'да ходимлар рўйхати. «Unit қўшиш» (parent
  танлаш), «Ходим жойлаш» (type=EMPLOYEE комбобокс).
- **/org/{id}/units...** - unit CRUD (ном/код/parent/active).
- Ходим кўриниши (келажакда profile/employee'да): у қайси
  тузилмаларда қайси unit'да - read-only рўйхат.
- Бошқарув: **SUPER_ADMIN** (ва админ рол) - 092 UrlPermissionMap'га
  `/org/**` янги соҳа ёки SETTINGS остида (картада ҳал). Кўриш кенгроқ
  роллга очилиши мумкин (фойдаланувчи кейин айтади).

## BR кодлар (КАТАЛОГ-АВВАЛ, grep билан)

Битта ходим бир тузилмада битта unit (UNIQUE + BR-ORG); unit ўз
тузилмаси ичидаги parent'га боғланади (бошқа тузилма unit'и parent
бўлмайди); дарахтда цикл тақиқи (parent ўзи/авлодига эмас); фаол
тузилмада камида... (шарт эмас - бўш тузилма мумкин).

## Тестлар (минимум)

Тузилма+unit дарахти CRUD; ходим бир тузилмада иккинчи unit'га
жойлаш → BR рад; ходим ҳар хил тузилмаларда қатнашади (иккита
ёзув, тўқнашмайди); parent цикл тақиқи; фаол/нофаол; web render
(дарахт + ходимлар); 375px; @WithMockRole SUPER_ADMIN кўради,
паст роль йўқ. Changeset dev boot ddl validate.

## 2-босқич (ҳозир ЭМАС - фойдаланувчи «кейин Class каби қўшамиз»)

- **Транзаксияга тег**: unit'ни ҳужжат/сатрга тег (Class каби) →
  «P&L by unit/branch/department» ҳисоботи (ProfitAndLossByClass
  нақши). Қайси тузилма бўйича тег - фойдаланувчи танлови.
- **Кириш назорати**: user (app_user↔employee орқали) ўз unit'и
  маълумотини кўради; branch менежери фақат ўз филиали - 092 роль
  тизимига чуқур уланиш.
- **Раҳбар/бўйсуниш** (org-chart reporting lines), unit ↔ warehouse
  боғланиши, ходим тарихи (қачон қайси unit'да).
