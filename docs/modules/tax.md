# Tax - ҚҚС каталоги ва ҳужжат солиғи (task #35) - SPEC

## Мақсад
QBO global (VAT) услубидаги солиқ: TaxRate каталоги, Bill/Invoice
сатрида ставка танлаш, GL'да ҚҚС контрол счёти. Ўзбекистон MVP:
ҚҚС 12% (seed). Ғоя манбаси: docs/old-erp-ideas.md §7 (оддий каталог).
Проводкалар: docs/posting-rules.md «Солиқ» бандлари (шу spec билан

## Қатъий қарорлар (2026-07-07 тасдиқланган)
- **Иккала нарх режими дарҳол** (QBO «Amounts are» паритети): ҳужжат
  сарлавҳасида танлов - «Суммалар ҚҚСсиз» (exclusive, default) ёки
  «Суммалар ҚҚС билан» (inclusive). Учинчи QBO ҳолати (Out of scope)
  алоҳида қилинмайди - барча сатр солиқсиз бўлса ўзи шу.
- **Ставка ҲАР САТРДА танланади** (QBO услуби): item'даги default'дан
  prefill, аралаш ҳужжат (солиқли + солиқсиз сатр) мумкин.
- **Битта контрол счёт**: SALES_TAX_PAYABLE тизим счёти (мавжуд detail
  type) - сотувда Cr (output), харидда Dt (input, ҳисобга олинадиган);
  қолдиқ нетто тўланадиган/қайтариладиган ҚҚС (QBO VAT control услуби).
  Янги detail type киритилмайди.
- **Ставка snapshot** (Money.exchangeRate / UoM unit_factor паттерни):
  сатрга ставка ҚИЙМАТИ ёзилади - каталогда кейин ўзгарса тарихий
  ҳужжат бузилмайди. Каталогда ставкани таҳрирлаш эркин.
- **Харид ҚҚСи таннархга кирмайди**: ITEM сатрда омборга НЕТТО қиймат
  киради, ҚҚС контрол счётига алоҳида (ҳисобга олинадиган ҚҚС).
- Тўловлар/aging/balance due ЎЗГАРМАЙДИ - улар gross (ҚҚСли) жамида
  ишлайверади, ҳужжат жамиси энди gross.

## Модел (changeset 032)

### TaxRate (tax_rate) - янги каталог
| Майдон | Тип | Изоҳ |
|---|---|---|
| code | varchar(20) unique | «QQS12», «NO_TAX» |
| name | varchar(100) | «ҚҚС 12%» |
| rate | numeric(9,4) | Фоиз: 12 = 12%. CHECK 0..100 |
| active | boolean default true | Нофаол янги ҳужжатда танланмайди |

Seed: `QQS12` («ҚҚС 12%», 12) ва `NO_TAX` («ҚҚСсиз», 0). Ўчириш йўқ -
active=false (каталог қоидаси). Ставка таҳрири эркин - ҳужжатлар
snapshot сақлайди.

### Item - кенгайтма (UoM default'лари паттерни)
| Майдон | Тип | Изоҳ |
|---|---|---|
| sales_tax_rate_id | UUID nullable (FK tax_rate) | Invoice сатрида prefill |
| purchase_tax_rate_id | UUID nullable (FK tax_rate) | Bill сатрида prefill |

null - prefill бўш (солиқсиз). Формада Сотув бўлимига сотув солиғи,
Харид бўлимига харид солиғи select'и қўйилади.

### Bill / Invoice - сарлавҳа кенгайтмаси
| Майдон | Тип | Изоҳ |
|---|---|---|
| amounts_inclusive | boolean NOT NULL default false | false - нархлар ҚҚСсиз (exclusive), true - ҚҚС ичида |

### BillLine / InvoiceLine - кенгайтма
| Майдон | Тип | Изоҳ |
|---|---|---|
| tax_rate_id | UUID nullable (FK tax_rate) | Танланган ставка; null - солиқсиз (эски сатрлар ҳам) |
| tax_rate_value | numeric(9,4) nullable | SNAPSHOT: сатр ёзилган пайтдаги фоиз |
| tax_amount | numeric(19,4) NOT NULL default 0 | Сатр ҚҚСи, ҳужжат валютасида |

`amount` семантикаси САҚЛАНАДИ: НЕТТО (солиқсиз) сумма - GL дебет/
даромад асоси. Gross = amount + tax_amount. Ҳужжат total энди
Σ(amount + tax_amount) - AP/AR, balance due, тўловлар шунга ишлайди.

## Ҳисоблаш (validate'да, ҳужжат валютасида, scale 4 HALF_UP)
Сатрда киритилади: qty, unit price, ставка. r = rate/100.

- **Exclusive** (default): net = qty × price (мавжуд формула);
  tax = round(net × r); gross = net + tax.
- **Inclusive**: gross = qty × price; net = round(gross ÷ (1 + r));
  tax = gross − net (АНИҚ КОМПЛЕМЕНТ - яхлитлаш дрейфи йўқ:
  net + tax == gross айнан).
- Ставка null/0 (NO_TAX): tax = 0, иккала режимда net = qty × price.
- unit_factor (UoM) билан бирга ишлайди - солиқ сатр суммасидан
  ҳисобланади, бирликка боғлиқ эмас.

## GL (posting-rules.md «Солиқ» бандлари)
Мавжуд JE ичига қўшимча сатр(лар) - янги ҳужжат тури йўқ:

- **Invoice post**: AR Dt = gross total; ҳар сатр даромад Cr = net;
  ҚҚС Cr = Σ tax **ставка кесимида жамланган** сатр(лар) (ҳужжатда
  неча хил ставка бўлса шунча сатр; нол жами - сатр ёзилмайди);
  COGS блоки ўзгармайди (home таннарх).
- **Bill post**: ҳар сатр INVENTORY/EXPENSE/CLEARING Dt = net
  (омборга НЕТТО unit cost киради); ҚҚС Dt = Σ tax (ставка кесимида);
  AP Cr = gross total.
- ҚҚС счёти - SALES_TAX_PAYABLE тизим счёти (топилмаса BR-LED-021).
  Default chart'да тайёр: «ҚҚС тўланадиган» (default-chart.csv, код
  2110, postable) - қўшимча seed керак эмас.
- **Чет валюта penny rounding**: мавжуд MoneyAllocation оқимига ҚҚС
  сатрлари ҳам киради - назорат сатри (AR/AP) base'и gross total ×
  rate'нинг битта яхлитлаши, қолган сатрлар (net'лар + ҚҚС'лар)
  largest-remainder билан айнан шу target'га тақсимланади
  (Beruniy-001/007 паттерни бузилмайди).
- **Reverse**: оддий GL сторно (reverseBySource) - ўзгариш йўқ.
- Тўлов/realized курс фарқи оқимларига тегилмайди (gross устида).

## Экранлар
- **/settings/tax-rates** (SETTINGS соҳаси, units паттерни): рўйхат + қўшиш/
  таҳрир (код, ном, фоиз, фаол). Settings каталог ҳаволаларига қўшилади.
- **Bill/Invoice формалари**: сарлавҳада «Суммалар: [ҚҚСсиз | ҚҚС
  билан]» select (amounts_inclusive); ҳар сатрда ставка select (item
  default prefill - itemMeta JS луғатига қўшилади); жонли жами блоки
  кенгаяди: Оралиқ жами (net) / ҚҚС / Жами (gross) - Nargiza-004/005
  жонли ҳисоблари билан мос.
- **Кўриш экранлари**: сатрда ҚҚС устуни (ставка % + сумма), пастда
  Оралиқ жами / ҚҚС / Жами қаторлари.
- **Item формаси**: Сотув/Харид бўлимларида default солиқ select'лари.
- Trial Balance/BS/P&L га алоҳида ҳеч нарса керак эмас - ҚҚС контрол
  счёти OTHER_CURRENT_LIABILITY сифатида ўзи кўринади.
- **Нетто дебет ҚҚС - онгли қабул қилинган соддалаштириш (Komil-009,
  Arbitr-026 (а) варианти)**: кирувчи ҚҚС чиқувчидан ошса, контрол
  счёт қолдиғи дебетга ўтади ва балансда мажбурият бўлимида МАНФИЙ
  сатр бўлиб кўринади. IAS 1.54(n) аслида буни актив (солиқ қайтариб
  олиш ҳуқуқи) сифатида кўрсатишни талаб қилади, лекин reclass
  қилинмайди: QBO ҳам GST/VAT контролни бир томонда ушлайди, кичик
  бизнесда бу ҳолат вақтинча (кейинги сотув ҳисобига ёпилади) ва
  автоматик reclass фойдаланувчини чалғитарди. Ҳолат доимийлашса
  (давр охирида барқарор дебет қолдиқ) - бухгалтер уни қўлда journal
  entry билан алоҳида «ҚҚС қайтарилиши» активига ўтказади.

## Тестлар (мажбурий рўйхат)
- Каталог: seed мавжуд, код unique (BR-TAX-001), 0..100 (BR-TAX-002),
  нофаол рад (BR-TAX-003).
- Exclusive: 1000 × 12% → net 1000 / tax 120 / gross 1120; GL: AP Cr
  1120, expense Dt 1000, ҚҚС Dt 120 (bill); invoice кўзгуси (AR Dt
  1120, даромад Cr 1000, ҚҚС Cr 120). debit == credit.
- Inclusive: gross 1120 → net 1000 / tax 120 (комплемент аниқ);
  қолдиқли ҳолат: gross 100, 12% → net 89.2857 → 89.2857? scale 4:
  net 89.2857, tax 10.7143, йиғинди айнан 100.
- Аралаш ҳужжат: солиқли + NO_TAX сатр - ҚҚС фақат биттасидан;
  икки хил ставка - иккита ҚҚС GL сатри.
- ITEM сатрли bill: омборга НЕТТО қиймат кирганини assert (unit cost =
  net/qty); reverse айнан қайтади.
- Ставка snapshot: draft'дан кейин каталогда ставка ўзгарса post
  draft'даги қийматни ишлатади.
- Чет валюта + ҚҚС: MoneyAllocation билан ҳар сатр BR-LED-003 ичида,
  йиғинди BR-LED-006.
- Balance due/тўлов gross устида ишлашини кўрсатувчи битта оқим тести.
