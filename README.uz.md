# Averpo ERP

**Ўзбекистондаги кичик ва ўрта бизнес учун иккиёқлама ёзувли молия тизими** -
бухгалтерия ядроси, сотув, харид, кўп-омборли инвентар, банк, ойлик ва IFRS
услубидаги молиявий ҳисоботлар. Ҳаммаси битта иловада, ўз серверингизда.

Java 21 / Spring Boot 4, сервер томонда рендер (JTE + HTMX), SPA framework йўқ,
CDN'га боғлиқлик йўқ, ишлаши учун ташқи хизмат талаб қилинмайди.

## 1. Лойиҳа нима учун керак

Ўзбекистондаги кичик ва ўрта бизнес бугунги дастурий таъминот билан яхши
таъминланмаган:

- **Глобал булут маҳсулотлар** (QuickBooks Online, Xero) бу ерга
  мослаштирилмаган: ўзбек тили йўқ, сўм биринчи ўринда эмас, маҳаллий банк ва
  солиқ амалиёти ҳисобга олинмаган, тўлов эса ҳар компания учун ойлик чет
  валютада.
- **Йирик ERP'лар** (SAP, Oracle NetSuite) 5-50 кишилик компания учун ҳам жуда
  қиммат, ҳам оғир - доимий жорий этувчи шерик талаб қилинади.
- **Excel жадваллари** амалда асосий восита бўлиб қолмоқда. Улар иккиёқлама
  ёзувни мажбурламайди, балансланиши исботланадиган Баланс бермайди ва аудит
  изини қолдирмайди.

Averpo айнан шу оралиқни тўлдиради: **ҳақиқий ERP даражасидаги бухгалтерия
қатъийлиги, лекин кичик бизнес маҳсулотининг соддалиги билан** - ўзбек тилида,
сўмда, битта оддий серверда.

## 2. Қиёсий тадқиқот: нималарни ўргандик

Лойиҳа бўшлиқда лойиҳаланмаган. Домен моделини ёзишдан олдин тўртта етакчи
тизимни - **QuickBooks Online, Xero, Oracle NetSuite ва SAP S/4HANA** - уларнинг
**бирламчи** манбаларидан ўргандик: расмий XSD схемалар, SDK'лар, API
ҳужжатлари ва вендор help тизимлари. Блог мақолаларидан эмас.

### 2.1 QuickBooks Online - эталон

QuickBooks Online бизнинг **мажбурий дизайн эталонимиз**. Дизайн саволига икки
хил оқилона жавоб бўлса - аввал QBO текширилади ва унга эргашилади.

Intuit'нинг ўз артефактлари билан ишлаймиз:

- Расмий [QuickBooks V3 Java SDK](https://github.com/intuit/QuickBooks-V3-Java-SDK)
  таркибидаги **`Finance.xsd`** ва **`IntuitNamesTypes.xsd`** (`ipp-v3-java-data`,
  Apache 2.0) - [`docs/qbo-reference/`](docs/qbo-reference/) га кўчирилган, шунинг
  учун ҳар бир даъвони текшириб кўриш мумкин.
- QBO entity'ларининг биздагилар билан майдонма-майдон солиштируви:
  [`docs/qbo-reference/entities.md`](docs/qbo-reference/entities.md).

Схемадан бевосита олинган асосий нарсалар:

- **Уч поғонали счётлар режаси** (`Classification → AccountType → AccountSubType`),
  расмий `AccountSubType` номлари билан бирга.
- **`Transaction` супертипи**: QBO'нинг ўз объект моделида ҳар бир ҳужжат
  (`Invoice`, `Bill`, `Payment`, `JournalEntry`, `Transfer`...) умумий
  `Transaction` асосидан мерос олади - унда `DocNumber`, `TxnDate`,
  `CurrencyRef`, `ExchangeRate`, `Line[]`, `LinkedTxn[]` бор. Сотув ҳужжатлари
  `SalesTransaction`, харид ҳужжатлари `PurchaseByVendor` орқали давом этади.
- **Битта ҳужжат = битта валюта ва битта курс** қоидаси (иккови ҳам сарлавҳада,
  сатрда эмас).

QBO'дан **атайлаб фақат икки жойда** фарқ қиламиз, иккови ҳам ҳужжатланган:

1. **Кўп-омборли инвентар** (+ landed cost, ўлчов бирликлари каталоги) - QBO'да
   омбор тушунчаси умуман йўқ.
2. **Payroll Lite** - ойлик ҳисоби QBO ядросига кирмайди.

QBO'да йўқ бошқа ҳеч нарса қўшилмайди.

### 2.2 Xero - 2026 йил август ҳолатига текширилган

Xero [Accounting API](https://developer.xero.com/documentation/api/accounting/overview)
(OpenAPI v16.1.0) ва Xero Central орқали ўрганилди. У SME булут сегментидаги энг
яқин рақобатчи:

| Жиҳат | Xero | Averpo |
|---|---|---|
| Счётлар режаси | 2 поғона: 5 синф → 17 счёт тури | 3 поғона, QBO услубида |
| Invoice ва Bill | Битта entity, фақат `Type` билан фарқланади (`ACCREC`/`ACCPAY`) | Алоҳида ҳужжатлар, алоҳида проводка қоидалари |
| Инвентар баҳолаш | **Фақат ўртача нарх** - ядрода FIFO йўқ | **AVCO ёки FIFO**, компания танлайди, биринчи ҳаракатдан кейин қулфланади |
| Омборлар | **Ядрода йўқ.** Xero'нинг ўз FAQ'си: *«Xero'нинг асосий бухгалтерия дастури инвентарни бир нечта жойда кузатмайди»* - алоҳида *Inventory Plus* қўшимчаси бор, фақат АҚШда | Кўп-омбор доменнинг асосий қисми |
| Инвентар тузатиш | Алоҳида ҳужжат йўқ - расмий ечим нол суммали счёт-фактура/кредит-нота | Алоҳида тузатиш ва кўчириш ҳужжатлари |
| POSTED ҳужжатни таҳрирлаш | Тасдиқланган, тўланмаган счёт-фактура **суммаси билан таҳрирланади** | POSTED ўзгармас - фақат сторно |
| Давр ёпиш | Фақат lock date, администратор уни исталган пайт олиб ташлаши мумкин | Closing-date қулфи posting service'да мажбурланади (`BR-LED-020`) |
| Таҳлил кесимлари | Қатъий чегара: **2 та фаол** tracking category | Class tracking сатр даражасида |
| Гуруҳ консолидацияси | Стандарт тарифларнинг ҳеч бирида йўқ (Xero 2025 йил июлда *«ҳозирча режада эмас»* деган); фақат 2026 йил июлда Syft орқали, Австралияга хос янги *Xero Ultra* тарифида пайдо бўлди | Multi-tenant дизайни жараёнда |

### 2.3 Oracle NetSuite

[NetSuite Help Center](https://docs.oracle.com/en/cloud/saas/netsuite/ns-online-help/)
орқали ўрганилди. NetSuite QBO'нинг архитектуравий қарама-қарши чеккасида:

- **Ҳамма нарса битта транзакция жадвалида.** NetSuite барча ҳужжат турини
  битта `transaction` жадвалида `TYPE` устуни билан ажратади; сатрлар
  `transactionline`, ҳақиқий GL дебет/кредит эса учинчи жадвалда -
  `transactionaccountingline`.
- **Етти хил костинг методи** - Average (default), FIFO, LIFO, Standard, Group
  Average, Specific, Lot Numbered - ҳақиқий партия-даражасида.
- **Void семантикаси созламага боғлиқ.** Default ҳолатда void **оригиналнинг
  ўзини ўзгартиради** (суммани нолга туширади). *Void Transactions Using
  Reversing Journals* ёқилса - оригинал сақланади ва санали сторно ёзуви
  қўшилади, лекин ўшанда счёт-фактура, кредит-нота ва нақд сотув умуман void
  қилинмайди.
- **OneWorld / Multi-Book** - кўп-филиал ва параллел бухгалтерия китоблари;
  бизнинг multi-tenant режамизга энг яқин аналог.

**Нимани олдик**: discriminator нақши (бизнинг `BankTransaction` - кирим/чиқим/
ўтказма битта жадвалда) ва сторно ёпиқ даврни қайта ёзмасдан **очиқ даврга**
тушиши керак деган принцип.

**Нимани олмадик**: барча ҳужжат учун битта улкан жадвал. Invoice, тўлов, харид
буюртмаси ва проводка чинакам ҳар хил шакл ва инвариантларга эга; уларни
бирлаштириш constraint кучини йўқотади ва жуда кенг, сийрак жадвал беради.

### 2.4 SAP S/4HANA

SAP'нинг расмий ўқув материаллари, Help Portal ва Knowledge Base мақолалари
орқали ўрганилди. SAP бизнинг архитектурамизга энг кучли таъсир қилган ғояни
берди:

- **Икки қатлам.** Операцион ҳужжатлар ҳар домен бўйича алоҳида (`VBAK`/`VBAP`
  сотув, `EKKO`/`EKPO` харид, S/4HANA'да `MATDOC` товар ҳаракати) ва account
  determination орқали бухгалтерияга проводка қилади. Бухгалтерия ҳужжати
  операцион ҳужжатдан алоҳида.
- **Universal Journal** (`ACDOCA`, SAP S/4HANA Finance 1503 да киритилган) FI,
  CO, актив ҳисоби ва material ledger'ни битта сатр жадвалига бирлаштиради -
  субледжерлар орасидаги солиштириш зарурати йўқолади.
- **Post қилинган суммалар ўзгармас.** Тузатиш мажбурий сабаб коди билан сторно
  орқали; кейин фақат қиймат бўлмаган майдонлар (референс, изоҳ) ўзгартирилади.
- **Перпетуал баҳолаш - moving average ёки standard price.** SAP'даги FIFO/LIFO
  - бу **даврий баланс баҳолаш жараёни**, партия-даражасидаги доимий костинг
  ЭМАС. LIFO эса S/4HANA Cloud'да умуман қўллаб-қувватланмайди, чунки халқаро
  стандартларда рухсат этилмаган.

Averpo айнан шу икки-қатлам фалсафасига амал қилади: **ҳужжатлар операцион,
ledger эса ягона молиявий ҳақиқат**, ва post қилинган ёзувлар ўзгармас.

## 3. Бухгалтерия стандартлари (IFRS / IAS)

Счётлар режаси ва молиявий ҳисоботлар **IFRS тақдимоти** бўйича қурилган.
Кодга бевосита таъсир қилган стандартлар:

| Стандарт | Қаерда амал қилади |
|---|---|
| **IAS 1** - *Молиявий ҳисоботлар тақдимоти* | Баланс ва Фойда-зарар тузилмаси; Баланс `актив = мажбурият + капитал` тенглигини текширади, жорий йил фойдаси тақсимланмаган фойдадан молия йили бўйича ажратилади |
| **IAS 2** - *Захиралар* | Захиралар таннархи **ўртача нарх (AVCO)** ёки **FIFO** билан ўлчанади - IAS 2 рухсат берган икки метод. **LIFO амалга оширилмаган, чунки IAS 2 уни тақиқлайди.** Таннарх `(товар, омбор)` кесимида ҳисобланади |
| **IAS 21** - *Валюта курслари ўзгаришининг таъсири* | Home (функционал) валюта компания даражасида белгиланади ва биринчи post қилинган ёзувдан кейин қулфланади; операциялар битим санасидаги курс бўйича ёзилади; тўлов пайтидаги реализация қилинган курс фарқи фойда-зарарга тушади |
| **IFRS 15** - *Харидорлар билан шартномалардан даромад* | Даромад сотув ҳужжати post қилинганда тан олинади, солиқ ва таннархдан ажратилган ҳолда |
| **IFRS 9** - *Молиявий инструментлар* | Дебитор ва кредиторлик қарзлари; AR/AP муддат таҳлили |
| **IAS 7** - *Пул оқимлари ҳисоботи* | Dashboard'даги пул ҳаракати (тўлиқ ҳисобот - режада) |

Иккиёқлама ёзув ядроси бухгалтерия тенгламасини одат билан эмас, **тузилмавий**
мажбурлайди: **ҳар проводка home валютада балансланади
(`sum(debitBase) = sum(creditBase)`) ва бу ҳар қоида учун unit test билан
исботланади**, ҳамда қолдиқлар фақат бош китобдан ҳисобланади - ҳеч бир модул ўз
жамини сақламайди.

Бу халқаро касбий уюшмалар (ACCA, ICAEW) ўргатадиган ва IFRS билан ишлайдиган ҳар
қандай бухгалтер кутадиган модель. Стандартлар матни IFRS Foundation томонидан
[ifrs.org](https://www.ifrs.org/issued-standards/list-of-standards/) да чоп
этилади; бу ерда фақат рақами билан ҳавола қилинади.

## 4. Ўзбекистонга мослаш

Глобал маҳсулотлар бошқа бозорлар учун қурилган. Бу ерда муҳим бўлган
мослашувлар:

- **Ўзбек тили биринчи ўринда.** Бутун интерфейс ўзбекча (кирилл), ёнида рус ва
  инглиз - ҳар тилда 1 762 таржима калити. Қисман таржима эмас: ҳар экран, ҳар
  хабар ва ҳар бизнес-қоида хатоси.
- **Home валюта сифатида сўм**, лекин ҳақиқий савдо учун зарур кўп-валюта
  механизми билан (USD'да олиб, сўмда сотиш). Курслар **Ўзбекистон Марказий
  банкидан кунига икки марта автоматик** тортилади ва компания қайси валютада
  ҳисоб юритишидан қатъи назар тўғри pivot қилинади.
- **Рақам ва пул форматлари маҳаллий ўқиш одатига мос**: каср нуқта билан, минг
  ажратгичи узилмас бўшлиқ (`12 600.50`), пул доим валюта коди билан, миқдор
  доим бирлиги билан.
- **ҚҚС тўлақонли каталог сифатида**, ҳар сатрда ставка snapshot'и - каталог
  кейин ўзгарса тарихий ҳужжат бузилмайди.
- **Payroll Lite** маҳаллий ушлаб қолиш тузилмаси билан (даромад солиғи, пенсия,
  ижтимоий бадал ставкалари созламада) - QBO эталонидан атайлаб ташқарида, чунки
  бу ердаги кичик бизнес ойликни ҳам шу тизимда кутади.
- **Ўз серверида, битта машинада ишлайди.** Чет валютадаги обуна ҳам, узоқдаги
  хизматга боғлиқлик ҳам йўқ.
- **Кўп-омборли инвентар** - савдо компанияларига зарур, лекин QuickBooks Online
  ҳам, Xero ҳам буни ядросида бермайди.

## 5. Архитектура

### 5.1 Modular monolith

Микросервис эмас. Пакетлар бизнес модул бўйича ташкил этилган
(`com.averpo.erp.<module>.{domain,service,repo,web}`) ва модуллар бир-бири билан
**фақат public service интерфейслари орқали** гаплашади - бошқа модулнинг
repository'сига тегиш тақиқ. Боғлиқликлар битта йўналишда: ledger томон, ledger
эса ҳеч кимга боғлиқ эмас.

```
sales · purchase · bank · inventory · payroll · pricing · tax · contact · item
                                  ↓
                          ledger (PostingService)
                                  ↓
                    journal_entry / journal_entry_line
```

### 5.2 Ledger - ягона ҳақиқат манбаси

Ҳеч бир модул қолдиқ сақламайди. Ҳар қолдиқ, ҳар ҳисобот рақами ва ҳар dashboard
кўрсаткичи бош китобдан ҳисобланади.

Ҳужжат post қилинганда `PostingService` чақирилади; у проводкани яратиб,
`sourceModule` + `sourceDocumentId` билан ҳужжатга боғлайди. Post қилинган ёзув
ўзгармас; хато сторно ёзуви билан тузатилади, ҳеч қачон update билан эмас.

### 5.3 Ҳужжат ҳаёт цикли

```
DRAFT  →  POSTED  →  REVERSED
эркин     GL'да       сторно
таҳрир    проводка    ёзуви
```

Харид буюртмаси ва таклиф (Estimate) атайлаб GL'сиз: ҳужжат оқимида
қатнашади, лекин бош китобга тегмайди.

### 5.4 Персистенция

- **UUIDv7 асосий калитлар**, конструкторда тайинланади (вақт бўйича тартибли,
  индексга қулай) - Hibernate генератори эмас.
- Пул `NUMERIC(19,4)`, курс `NUMERIC(24,12)` - тескари курслар
  (`1 UZS = 0.000082690073 USD`) ҳам саккиз маъноли рақам сақлаши учун.
- **Схеманинг ягона эгаси - Liquibase** (62 кетма-кет миграция); Hibernate
  `validate` режимида ишлайди ва ҳеч қачон DDL яратмайди.
- Барча вақтлар UTC'да сақланади, экранда компания вақт минтақасида кўрсатилади.

## 6. Темир қоидалар

Ҳар code-review текширадиган ўн учта инвариант. Тўлиқ матни:
[`docs/engineering-rules.md`](docs/engineering-rules.md).

1. Пул - `Money` value object, ҳеч қачон `double`/`float` эмас.
2. Бош китобга фақат `PostingService` ёзади.
3. POSTED ҳужжат ҳеч қачон ўзгартирилмайди - фақат сторно.
4. Ledger home валютада балансланади: `sum(debitBase) = sum(creditBase)`.
5. Ҳар схема ўзгариши - янги Liquibase changeset.
6. Модуллараро мурожаат фақат service интерфейси орқали.
7. Ҳар проводка қоидасига дебет = кредит текширадиган тест.
8. Проводкалар [`docs/posting-rules.md`](docs/posting-rules.md) га аниқ мос.
9. Инвентар баҳолаш (AVCO/FIFO) компания даражасида танланади ва биринчи омбор
   ҳаракатидан кейин қулфланади.
10. Ҳар field ва метод «нега» кераклигини тушунтирувчи изоҳга эга.
11. Валюта - каталог entity'си; `Money` ичида ISO код сақланади.
12. Барча вақтлар UTC'да.
13. Бизнес қоида бузилиши - [`docs/business-rules.md`](docs/business-rules.md)
    даги ноёб `BR-*` код билан `BusinessRuleException`.

## 7. Имкониятлар

**Бухгалтерия ядроси** - IFRS услубидаги счётлар режаси (3 поғона, QBO
таксономияси), қўлда проводкалар, бошланғич қолдиқлар, давр ёпиш қулфи, аудит
журнали.

**Сотув** - Счёт-фактура, Sales Receipt, Таклиф, Кредит-нота, Refund Receipt,
мижоз тўловлари (бир нечта ҳужжатга тақсимлаш билан), AR муддат таҳлили, кредит
лимити, поғонали нарх рўйхатлари.

**Харид** - Bill, Харид буюртмаси (GL'сиз), Vendor Credit, таъминотчи тўловлари,
AP муддат таҳлили, **landed cost** тақсимоти.

**Инвентар** - кўп-омборли қолдиқлар, `(товар, омбор)` кесимида AVCO ёки FIFO,
кирим, чиқим, тузатиш, кўчириш, конверсия коэффициентли бирлик гуруҳлари,
исталган санага инвентар баҳоси ҳисоботи.

**Банк** - банк счётлари, кирим, чиқим, ўтказмалар, автоматик курс фарқи билан
валюта конверсияси, reconciliation.

**Payroll Lite** - ходимлар, ставкалар, ойлик ҳисоблаш, қисман тўлов, ведомость.

**Ҳисоботлар** - Баланс, Фойда-зарар, Айланма қайднома, йўналиш кесимида
Фойда-зарар, drill-down билан AR/AP муддат таҳлили, инвентар баҳоси, мижоз
ҳисобварағи ва QBO услубидаги dashboard.

**Платформа** - соҳага асосланган рухсатли 8 роль, аудит изи, ҳужжат
иловалари, глобал қидирув, Excel'дан бошланғич импорт, уч тил, оч/тўқ режим,
mobile-first (ҳар экран 375px да ишлайди).

## 9. Сифат ва муҳандислик интизоми

## 10. Ишга тушириш

**Талаблар:** JDK 21, PostgreSQL 18.

```bash
# 1. База ва роль
psql -U postgres -c "CREATE ROLE averpo LOGIN PASSWORD 'averpo';"
psql -U postgres -c "CREATE DATABASE averpo OWNER averpo;"

# 2. Ишга тушириш - Liquibase схемани қуради, стандарт счётлар режаси seed бўлади
./gradlew bootRun --args='--spring.profiles.active=dev'
```

<http://localhost:8080> ни очиб `admin` билан киринг. `dev` да парол автоматик
seed қилинади; production'да `AVERPO_ADMIN_PASSWORD` **мажбурий** - усиз илова
умуман ишга тушмайди.

**Демо маълумот.** `demo` профили тўқима савдо компаниясини яратади - мижозлар,
таъминотчилар, товарлар, post қилинган счёт-фактура, bill ва тўловлар - шунда
ҳисоботлар ва dashboard мазмунли рақамлар кўрсатади:

```bash
./gradlew bootRun --args='--spring.profiles.active=dev,demo'
```

**Тестлар** (номи `_test` билан тугайдиган база талаб қилинади - қоровул бошқа
базада ишлашга йўл қўймайди):

```bash
psql -U postgres -c "CREATE DATABASE averpo_test OWNER averpo;"
./gradlew test
```

## 11. Режа

**Multi-tenant SaaS.** Кейинги катта босқич Averpo'ни кўп-компаниялик платформага
айлантиради: битта PostgreSQL базаси `tenant_id` устуни билан, Hibernate'нинг
native `@TenantId` фильтри, иккинчи ҳимоя қатлами сифатида PostgreSQL row-level
security ва мавжуд URL'ларни ўзгартирмайдиган session-асосли tenant аниқлаш.
Тўлиқ режа:
[`docs/multi-tenant-plan/plan-for-averpo.md`](docs/multi-tenant-plan/plan-for-averpo.md).

**Бухгалтер портали.** Битта бухгалтер - кўп компания. Ўзбекистондаги аутсорс
бухгалтерия айнан шу моделда ишлайди: битта логин орқали ҳам ўз фирмасининг
китоблари, ҳам барча мижоз компаниялари; ходимларга эса ҳар мижоз бўйича алоҳида
рухсат.

**Яна режада:** такрорий операциялар, ҳужжат чоп этиш / PDF / email, банк
кўчирмасини импорт қилиш ва мослаштириш, ҚҚС даврий ҳисоботи, бюджетлаш.
