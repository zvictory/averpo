# Заводга қайтариш (Factory reset) - SPEC (ТАСДИҚЛАНГАН)

## Мақсад

Созламаларда «Ҳаммасини ўчириб бошланғич ҳолатга қайтариш» тугмаси
(фойдаланувчи талаби): демо/синов маълумотларини бир
босишда тозалаб, тизимни янги ўрнатилган ҳолатга келтиради.
Эталон: QBO «Purge company» (янги компанияда бор - аналог бор,
ўзимиз ўйлаб топмадик).

## Хавфсизлик оқими (фойдаланувчи талаби: пароль + икки босқич)

1. /settings пастида алоҳида **«Хавфли ҳудуд»** бўлими (қизил
 ҳошия): тугма «Заводга қайтариш...».
2. **1-босқич** (алоҳида саҳифа, қизил danger): нима ўчиши ТЎЛИҚ
 рўйхат билан огоҳлантирилади («Барча ҳужжатлар, проводкалар,
 контактлар, товарлар... БУТУНЛАЙ ўчади - қайтариб бўлмайди») +
 **admin ПАРОЛИНИ қайта киритади** (login маълум - жорий сессия).
3. **2-босқич** (пароль тўғри бўлгандан кейингина): «Қарорингиз
 қатъийми? Бу амални ортга қайтариб БЎЛМАЙДИ» + тасдиқ матни
 сифатида компания номини ёзиш талаб қилинади + якуний қизил
 тугма «Ҳа, ҳаммасини ўчир».
4. Фақат SUPER_ADMIN (SETTINGS соҳаси + @PreAuthorize гарови);
 ҳар босқич POST + CSRF; пароль текшируви
 AuthenticationManager орқали (BR-RST-001 нотўғри пароль,
 BR-RST-002 тасдиқ матни мос эмас).
5. Muvaffaqiyatdan кейин: сессия сақланади, redirect
 /settings?setup=1 - onboarding қайтадан бошланади (056 оқими).
 Серверда WARN лог ёзилади (ким, қачон).

## Нима ЎЧАДИ / нима ҚОЛАДИ («бошланғич ҳолат» таърифи)

ЎЧАДИ (тўлиқ TRUNCATE, битта транзакция, FK тартибида):
- Барча ҳужжатлар: invoice, bill, estimate, PO, CM, VC, RR,
 sales receipt, payroll run/payment, landed cost, bank txn,
 transfer, reconciliation, payment/application жадваллари.
- GL: journal_entry(_line). Inventory: stock movement'лар.
- Контактлар, товарлар (+нарх рўйхатлари), txn_class, валюта
 курслари, ҳужжат рақам счётчиклари (document_sequence seed
 ҳолатига), audit log.
- Иловалар: attachment ёзувлари + ДИСКдаги файллар
 (ATTACHMENTS_DIR ичи).

- Фойдаланувчилар: reset қилаётган super admin'дан БОШҚА ҳамма
 app_user ўчади (фойдаланувчи қарори: «фақат admin
 қолади»). Жорий super admin қолади (ўзини ўчириб қулфлаб
 қўймасин).

ҚОЛАДИ (ФАҚАТ янги ўрнатишда ҳам бирга келадиганлар - булар
фойдаланувчи маълумоти ЭМАС, тизим таркиби):
- Reset қилаётган admin (ягона фойдаланувчи).
- Seed каталоглар: счётлар режаси (default-chart), units 6 та,
 tax_rate 2 та, currency 7 та, «Асосий омбор» - ФАҚАТ seed
 сатрлари; фойдаланувчи қўшганлари ўчади (seed id/код рўйхатлари
 changeset'лардан олинади - фиксирланган UUID'лар). Excel import
 ҳам айнан шу seed'ларга таянади (бирлик/ҚҚС/валюта номлари).
- CompanySettings ҚАТОРИ default'га ҚАЙТАДИ: name «Компания»,
 UZS, default timezone, valuation unlock, closing null,
 **setup_done=false** (шунинг учун setup оқими қайта бошланади).
 Home currency қулфи табиий очилади (POSTED JE қолмайди).

## Дизайн қарорлари

- `shared.service.FactoryResetService.reset` - @Transactional,
 JdbcClient TRUNCATE/DELETE (бу МАЪМУРИЙ амал, ҳужжат lifecycle
 эмас - PostingService четлаб ўтилиши темир қоида 2/3 га зид ЭМАС,
 чунки ҳужжат ўзгартирилмаяпти - бутун тизим йўқ қилиняпти; шу
 истисно business-rules.md'да ҳужжатланади, BR-RST бўлимида).
- Диск файллари транзакциядан КЕЙИН ўчирилади (DB rollback бўлса
 файллар жойида қолсин); ўчириш хатоси reset'ни йиқитмайди
 (WARN лог).
- Тест: тўлдирилган база (ҳужжат+GL+каталог+иккинчи user) → reset →
 ҳар жадвал айнан seed ҳолати (счётлар/units/tax/currency/омбор
 сони seed'га тенг, қолганлари 0, app_user фақат reset қилган
 super admin, settings default, setup_done=false); пароль нотўғри →
 BR-RST-001, ҳеч нарса ўчмаган; SETTINGS соҳасисиз роль → 403.
- ScreenSmokeTest: /settings/reset GET (SUPER_ADMIN).
- Changeset КЕРАК ЭМАС.
