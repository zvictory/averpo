# Multi-currency (4-босқич) - SPEC

## Мақсад
Валюта курслари каталоги: қўлда киритиш + ЎзР Марказий банкидан (cbu.uz)
автоматик импорт, формаларда курс prefill. Money тузилмаси ўзгармайди
(amount + baseAmount + exchangeRate аллақачон бор) - бу босқич курс
МАНБАсини беради. Тўлиқ realized курс фарқи Invoice/Payment билан
6-7-босқичда (posting-rules.md да қоидалари тайёр); бу ерда қолипни
тасдиқлайдиган posting тест ёзилади.

## Entity
`shared.domain.ExchangeRate`: currency (ManyToOne Currency), rate_date,
rate NUMERIC(24,12) CHECK > 0, source (RateSource: CBU/MANUAL).
1 currency = rate home семантикаси. APPEND-ONLY ТАРИХ (Arbitr-022,
changeset 033): бир (валюта, сана)га КЎП ёзув мумкин - UNIQUE
(currency_id, rate_date) 033'да олиб ташланган, ёзув устига
ёзилмайди; амалдаги курс = энг охиргиси (rate_date DESC, id DESC -
UUIDv7 тартиби). Lookup индекси: idx_exchange_rate_lookup
(changeset 035).

## Service API (shared)

### ExchangeRateService
- `Optional<BigDecimal> rateFor(String code, LocalDate date)` - шу
 санага тенг ёки ундан ОЛДИНГИ энг охирги курс (QBO услуби: курс
 кундалик, дам олиш кунида олдингиси амал қилади). Топилмаса бўш -
 фойдаланувчи қўлда киритади.
- `List<ExchangeRate> history(String code)` - UI учун, янгидан эскига.
- `ExchangeRate record(String code, LocalDate date, BigDecimal rate,
 RateSource source)` - тарихга ЯНГИ ёзув қўшади (append), мавжудни
 АЛМАШТИРМАЙДИ; фақат шу санадаги энг охирги ёзув билан айнан бир
 хил курс келса дубль ёзилмайди. MANUAL курс CBU устига ёзилмайди -
 ЁНИДА туради (аудит изи, source билан ажралади).
 BR-FX-001 (сана/мусбат қиймат), BR-FX-002 (home валютага тақиқ).
- `ExchangeRate upsert(String code, LocalDate date, BigDecimal rate)` -
 тарихий ном, амалда `record(..., MANUAL)` юпқа wrapper'и
 (чақирувчилар синмаслиги учун сақланган).
- `ImportResult importFromCbu(LocalDate date)` - фаол чет валюталар
 учун ЦБ курсини тортиб record(CBU) қилади. ЦБ жавобида йўқ валюта
 ўтказиб юборилади (result'да кўринади).

 **Санагич (Arbitr-168)**: `ImportResult` `checked` (текширилган),
 `changed` (қиймати олдинги амалдагидан ўзгарган) ва `skipped` (ЦБ'да
 йўқ)ни фарқлайди - дам олиш/такрор импортда ЦБ эски (жума) курсни
 қайтаради, валюта текширилади лекин ўзгармайди; аудит ва хабар
 «ўзгарди»ни фақат `changed>0` да айтади. Per-date ёзув сақланади
 (Currencies экрани бугунги санани кўрсатади - тизим ишлаяпти далили).

 **Pivot қоидаси (Arbitr-067, фойдаланувчи талаби)**: ЦБ
 ҳамиша «1 F = N UZS» беради, лекин импорт home currency ҚАНДАЙ
 бўлса ҳам ишлайди:
 - home = UZS: ЦБ қиймати ЎЗГАРИШСИЗ ёзилади (бўлиниш йўқ -
 аввалги йўл айнан, regression йўқ);
 - home ≠ UZS: кросс-курс UZS орқали pivot -
 `rate(home per F) = сўм/F ÷ сўм/home`, UZS'нинг ўзи фаол валюта
 бўлса унга `1 ÷ сўм/home`; иккала бўлиниш scale 12, HALF_UP
 (устун NUMERIC(24,12), changeset 005 - янги changeset керак эмас);
 - BR-FX-003 энди ФАҚАТ home≠UZS ва home валюта ЦБ рўйхатида
 бўлмаганда (pivot махражи йўқ - масалан ЦБ котировкаламайдиган
 home) ташланади; қўлда киритиш доим очиқ қолади.
 Кўрсатиш йўналиши (USD-устувор форматлаш) бу қоидага кирмайди -
 Arbitr-065 (ui-navigation-display.md E қисм).

### CbuRateClient (порт)
`rates(LocalDate)` - ЦБ JSON API
(`https://cbu.uz/uz/arkhiv-kursov-valyut/json/all/{sana}/`) дан
[валюта коди, курс] рўйхати. Тармоқ/формат хатоси - BR-FX-004.
Импл `RestClient`да; unit тестларда порт сохталанади, импл'нинг ўзи
MockRestServiceServer билан текширилади (тармоққа чиқилмайди).

**ЦБ Rate семантикаси (муҳим)**: жавобдаги `Rate` - `Nominal` дона
валюта учун сўмда. Ҳозирги ЦБ амалиётида Nominal ҳамма валютада 1
(текширилган: USD 11 909.66, RUB 152.28 - бирига), лекин
client ҳимоя учун Rate'ни Nominal'га бўлади: ЦБ кейинчалик арзон
валютани 10/100 номиналда эълон қилса ҳам курс «1 валюта = N сўм»
семантикасида тўғри қолади (бизнинг exchange_rate доим 1 донага).

### ExchangeRateScheduler
`@Scheduled` кунига икки марта (Тошкент вақти 10:00 ва 16:00,
ЦБ кундузи янгилайди) `importFromCbu(бугун)`. Хато boot/иловани
йиқитмайди - фақат warn log (офлайн муҳит нормал ҳолат, қўлда
киритиш доим очиқ). Arbitr-067'дан бери home≠UZS ҳам импорт
қилинади (pivot); фақат home ЦБ рўйхатида бўлмаса BR-FX-003
warn log'га тушади - scheduler барибир йиқилмайди.

### CurrencyService кенгайтмаси
- `setActive(String code, boolean active)` - валютани фаоллаштириш/
 нофаол қилиш (QBO Currencies услуби). BR-CUR-003: home валюта
 нофаол қилинмайди.

## Контакт валютаси ва ҳужжат валютаси (QBO ҚАТЪИЙ - фойдаланувчи қарори, Arbitr-087)

QBO'да ҳар customer/vendor'нинг битта валютаси бор ва AP/AR ҳужжат
валютасини АЙНАН КОНТАКТ белгилайди - ҳужжатда ўзгартирилмайди
(бошқа валюта керак бўлса янги контакт очилади). Биз шу қатъий
вариантни оламиз:

- `Contact.currency` (null = home) AP/AR контактли ҳужжатларда
 (Invoice, Bill, CreditMemo, VendorCredit, Estimate, PurchaseOrder,
 SalesReceipt, RefundReceipt) ҳужжат валютасини белгилайди; форма
 валюта майдони read-only кўрсатиш, server create/saveDraft'да
 мослик гарови (BR). Server валютани контактдан ўзи олади - client
 қийматига ишонилмайди.
- **Контакт валютаси қулфи**: контакт камида битта POSTED ҳужжатда
 қатнашган бўлса currency ЎЗГАРТИРИЛМАЙДИ (BR-CON янги код).
 Ўтиш қоидаси (мавжуд маълумот учун): null → қийматга БИРИНЧИ
 тўлдириш POSTED ҳужжатлар мавжуд бўлса ҳам мумкин, фақат янги
 қиймат ўша ҳужжатлар валюталарига зид бўлмаса; қийматдан қийматга
 ўзгартириш - доим тақиқ.
- Тегилмайдиганлар: Expense/BankTransaction (валюта тўлов счётидан,
 контакт ихтиёрий payee - QBO ҳам шундай), JournalEntry (сатр
 даражасидаги контакт - алоҳида мавзу), тўлов ҳужжатлари (валюта
 тўланаётган ҳужжатдан, мавжуд гаровлар), POSTED тарихий ҳужжатлар.
- Draft'да контакт алмашса валюта янги контактникига мослашади.

## Экранлар (2-туртки)
- `/settings/currencies` - **SETTINGS соҳаси (амалда SUPER_ADMIN)**
 (/settings/** соҳа қоидаси, QBO'да ҳам валюта бошқаруви company
 settings даражасида).
 Бухгалтерга керак бўлгани - курс prefill - /exchange-rates/lookup
 орқали барча авторизацияланганларга очиқ; ҳужжат ичида курсни қўлда
 ўзгартириш ҳам ҳар доим мумкин. Экран: валюталар жадвали (код, ном,
 белги, фаол тогл, охирги курс + санаси), «ЦБ дан импорт» тугмаси
 (сана танлаш, default бугун).
- `/settings/currencies/{code}/rates`: курс тарихи жадвали (Манба
 устуни: ЦБ/Қўлда; энг охирги ёзувда «амалда» байроқчаси) + қўлда
 қўшиш формаси (сана + курс - тарихга MANUAL ёзув қўшилади, эски
 сақланади).
- JE формаси: сатр валютаси ўзгарганда entry санасига кўра
 `GET /exchange-rates/lookup?currency=USD&date=...` дан курс олиниб,
 курс майдони тўлдирилади (қўлда ўзгартириш мумкинлигича қолади).
 Opening balance формасидаги курсга ҳам худди шу.

## Тестлар (мажбурий рўйхат)
- record: янги ёзув; ўша санага бошқа курс - ЯНГИ қатор қўшилади,
 эски сақланади (append-only), охиргиси амалда; айнан бир хил курс
 такрор келса дубль ёзилмайди; CBU ва MANUAL ёнма-ён сақланади.
- rateFor: айнан сана; олдинги сана (дам олиш куни); умуман йўқ - бўш.
- upsert home валютага - BR-FX-002; нол/манфий курс - BR-FX-001.
- importFromCbu (сохта client): фаол валюталар янгиланади, ЦБ'да йўқи
 ўтказилади, нофаол валюта олинмайди; home UZS эмас - BR-FX-003.
- CurrencyService.setActive: home'ни нофаол қилиш - BR-CUR-003;
 бошқасини нофаол/фаол қилиш ишлайди.
- Курс фарқи қолипи: ҳужжат курси 12 600, тўлов курси 12 700 - фарқ
 EXCHANGE_GAIN_OR_LOSS сатри билан балансланган JE post бўлади
 (debit == credit assert, posting-rules.md қолипи).
