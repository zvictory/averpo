# Банк кўчирмаси импорти (CSV) + мослаштириш - SPEC (тасдиқ КУТМОҚДА)

Манба: review/backlog/-DEC-042-bank-kochirma-import-csv.md
(NAVBAT 31-банд, фойдаланувчи 1.0 кўламига киритган).
БОҒЛИҚЛИК: 19-банд (BR i18n)дан КЕЙИН - янги BR кодлари янги i18n
қолипида туғилади (E-тўлқин қарори).

## Мақсад

Банк кўчирмасини (CSV) юклаб, сатрларини тизимдаги ҳужжатларга
мослаштириш (match) ёки бир босишда янги ҳужжат яратиш - QBO bank
feeds'нинг оффлайн муқобили. Ҳозир ҳамма банк операцияси қўлда
киритилади - бу энг катта кундалик вақт ютқизиғи. Реал bank feed
(Open Banking) Ўзбекистонда чекланган - CSV импорт амалий йўл
(ҳар банк CSV/Excel беради).

## QBO билан солиштирув

QBO Banking → «Upload from file» (CSV/QBO/OFX): устун харитаси
интерфейси, For review рўйхати, match таклифлари, Rules. Биз MVP'да:
CSV + устун харитаси + match таклифи + бир босишда яратиш. QBO
Rules («изоҳда X → Y счёт/контакт») - 2-БОСҚИЧ (онгли қисқартма,
эвристика аввал синалсин). OFX/QBO форматлар - 2-босқич.

## Оқим (MVP)

1. **Юклаш**: /bank-import (BANKING соҳаси) - банк ҳисоби танланади
   (BANK/CASH home ва чет валюта ҳам - кўчирма счёт валютасида),
   CSV файл юкланади.
2. **Устун харитаси**: биринчи қаторлар preview жадвали;
   фойдаланувчи устунларни белгилайди: сана / сумма (ёки алоҳида
   дебет+кредит устунлари - банклар иккала кўринишда беради) /
   изоҳ; «1-қатор сарлавҳа» белгиси; сана формати танлови
   (dd.MM.yyyy default). Кодировка авто: UTF-8 → бўлмаса CP1251
   (ўзбек банклари кўпинча Windows-1251 беради); сепаратор авто
   (; ёки ,). Харита кейинги импортга эслаб қолинади (банк ҳисоби
   бўйича - CompanySettings эмас, staging'нинг ўзида охиргиси).
3. **Импорт → staging (changeset 055)**: янги жадвал
   bank_statement_line: id, bank_account_id FK, stmt_date, amount
   (мусбат=кирим, манфий=чиқим), memo, line_hash (дубль guard),
   status NEW/MATCHED/CREATED/IGNORED, matched_txn_id nullable,
   imported_at, imported_by. ДУБЛЬ ҲИМОЯСИ: (bank_account_id,
   line_hash) UNIQUE - ўша файл қайта юкланса мавжуд сатрлар
   ўтказилади (Excel import идемпотент прецеденти).
4. **Match таклифи**: NEW сатр учун номзод - ўша счётдаги POSTED
   банк транзакцияси/ўтказмаси: сумма АЙНАН тенг + сана ±3 кун.
   Битта номзод - таклиф кўрсатилади, фойдаланувчи «Мослаштириш»
   босади (MATCHED + matched_txn_id); бир нечта - рўйхатдан танлайди.
5. **Яратиш**: мос ҳужжат йўқ бўлса «Яратиш» - кирим/чиқимга қараб
   банк транзакцияси формасига prefill линк (сана/сумма/изоҳ/счёт);
   сақлангач сатр CREATED + matched_txn_id. GL ёзуви ФАҚАТ мавжуд
   service орқали (қоида 2/6) - импортнинг ўзи GL'га ЁЗМАЙДИ.
6. **IGNORED**: банк комиссияси каби киритилмайдиган сатрлар қўлда
   белгиланади (сабабсиз, оддий тогл).
7. **Reconciliation алоқаси**: match/create қилинган ҳужжатлар GL'да
   бўлгани учун мавжуд reconciliation оқимига ўз-ўзидан тушади -
   алоҳида интеграция КЕРАК ЭМАС (икки марта саналмайди, чунки
   staging GL манбаси эмас).

## Дизайн қарорлари

- Staging сатри ҲУЖЖАТ ЭМАС: GL/posting йўқ, POSTED тушунчаси йўқ -
  оддий ҳолатли ёзув. PostingService import ҚИЛИНМАЙДИ (тест).
- Parse Apache POI ЭМАС - оддий CSV (String.split эмас, тирноқли
  қийматларни ҳисобга оладиган кичик парсер ёки commons-csv...
  ЯНГИ dependency ҚЎШИЛМАЙДИ - қўлда ёзилган кичик парсер, Excel
  import'даги хато-рўйхат услуби).
- Сумма парси FormParsers қолипида (вергул/НБСП қабул).
- BR оиласи: BR-BIM-001.. (таклиф - каталогга спец тасдиқлангач
  киради; файл формати/устун харитаси/дубль/сана парси хатолари) -
  имплементациядан АВВАЛ BR-BIM ва BR_BIM grep (SABOQLAR №4; BR-IMP
  Excel'га банд).
- Роллар: BANKING EDIT (092 дан кейин permission модели тайёр
  бўлади); VIEWER_AUDITOR'га фақат кўриш.
- Экран mobile-first: устун харитаси жадвали .table-wrap ичида.

## Тестлар (мажбурий рўйхат)

1. CSV parse: UTF-8 ва CP1251; «;» ва «,»; тирноқли изоҳ; дебет/кредит
   икки устунли вариант; хато сатрлар рўйхат бўлиб қайтади.
2. Дубль guard: ўша файл икки марта - иккинчисида 0 янги сатр.
3. Match номзоди: сумма тенг + сана ораликда топилади; икки номзодда
   иккиси ҳам таклифда; топилмаса бўш.
4. Status оқими: NEW→MATCHED (txn боғланади), NEW→CREATED,
   NEW→IGNORED; MATCHED сатр қайта match қилинмайди.
5. Импортда journal_entry сони ЎЗГАРМАЙДИ (staging GL ёзмайди).
6. ЖОНЛИ smoke: реал банк CSV намунаси (фойдаланувчидан сўралади -
   ҳақиқий формат!) юкланиб устун харитаси → импорт → битта match +
   битта create оқими (скриншот/DOM далил).

## 2-босқич (ҳозир ЭМАС)

- Rules («изоҳда X → авто-таклиф Y счёт/контакт», QBO Rules).
- OFX/QBO форматлар; Excel (.xlsx) кўчирма.
- Авто-match (тасдиқсиз) юқори ишонч ҳолатида; контакт эвристикаси.
