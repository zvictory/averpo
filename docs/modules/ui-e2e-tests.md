# UI E2E тест тўплами (Playwright) - SPEC (фойдаланувчи билан савол-жавобда келишилган)

## Мақсад

Фақат UI орқали, ҲАҚИҚИЙ браузерда юрадиган катта регресс тўплами:
илова кўтарилади, браузер ҳақиқий фойдаланувчидек ишлайди - формалар
тўлдиради, тугмалар босади, натижани экранда кўради. ФАҚАТ КЕРАК
БЎЛГАНДА қўлда ишга туширилади (доимий эмас - узоқ прогон).

Нега шарт: gradle web тестлар JS'ни умуман кўрмайди ва транзакцион
тестлар lazy/жонли хулқни ушламайди (SABOQLAR «СОХТА ЯШИЛ» - 054,
086, 079 form-layout: учаласини ҳам тестлар эмас, жонли кўрик тутди).
Бу тўплам айнан ўша синф хатоларни автоматлаштиради.

## Қарорлар (фойдаланувчи, - савол-жавоб натижаси)

1. **Восита**: Playwright for Java (`com.microsoft.playwright`,
   test-scope dependency; Node/npm КИРМАЙДИ). Биринчи прогонда
   браузер бинарлари юкланади (бир марта, кейин кеш).
2. **База**: алоҳида `averpo_ui_test` (номи '_test' билан
   тугайди - TestDbSafetyGuard талабига мос). TEST-NAVBAT навбатига
   КИРМАЙДИ - оддий тестлар ва coder'лар билан тўқнашмайди.
3. **Браузер**: фақат Chromium (headless default; debug учун headed
   режим -Duitest.headed=true).
4. **Қамров**: барча сценарий УЗбекчада + муҳим оқимларнинг 375px
   мобил варианти; ru/en учун биттадан тил-алмашиш smoke.
5. **MVP тўплами**: катта саёҳатлар + JS компонентлар (~50-70
   сценарий, тахминий прогон 10-20 дақиқа).
6. **Юритиш қоидаси (ДОИМИЙ)**: пойдевор+MVP'ни битта coder қуради;
   кейин ҲАР ЯНГИ feature картасига «UI тест банди» киради - тўплам
   feature билан бирга ўсади.
7. **Далиллар**: фақат ЙИҚИЛГАН тестда screenshot + Playwright trace
   (build/uitest-artifacts/; трейс қадамма-қадам қайта кўрилади).
8. **Флейк**: 1 автоматик ретрай; ретрайда ўтса FLAKY деб белгиланиб
   ҳисоботда кўринади (йиғилса алоҳида тузатиш тўлқини).

## Тузилма

- Алоҳида Gradle source set: `src/uiTest/java` + `uiTest` таски.
  `./gradlew test`га УЛАНМАЙДИ - фақат қўлда: `./gradlew uiTest`
  (қисман: `--tests "*.InvoiceJourneyTest"`).
- Тест ўзи иловани кўтаради: @SpringBootTest(webEnvironment =
  RANDOM_PORT) + Playwright ўша портга уланади - dev сервер (8080)
  билан тўқнашмайди, битта буйруқ билан ҳаммаси.
- Профиль `uitest`: ui_test база URL, admin пароли test-properties
  орқали (мавжуд test профили қолипи); DefaultChartInitializer каби
  seeder'лар хулқи test профили билан бир хил кўриб чиқилади.
- Login ҲАҚИҚИЙ UI орқали (login саҳифаси + парол киритиш тести ҳам
  қамров қисми); сессия context per-suite реюз (тезлик).
- **Ҳолат изоляцияси**: ҳар suite олдидан база ТОЗА ҳолатга
  келтирилади (schema Liquibase'дан бир марта; маълумот - truncate +
  seed helper, factory-reset service қолипи). Сценарийлар бир-бирига
  боғланмайди; тартибдан мустақил.
- Page Object қатлами: `pages/` (LoginPage, InvoiceFormPage, ...) -
  селекторлар бир жойда, JTE ўзгарса битта жой тузатилади.
  Селекторлар афзал тартиби: роль/label (getByRole/getByLabel) →
  id → CSS (тестга махсус data-testid фақат иложсиз жойда).

## MVP сценарий каталоги (~50-70)

**Саёҳатлар (ҳар бири тўлиқ оқим, GL/қолдиқ текшируви экран орқали):**
setup оқими (reset → биринчи созлаш); мижоз+товар яратиш → invoice
(combobox билан) → POSTED → тўлов → AR ёпилди → P&L/BS'да акс;
таъминотчи → PO → bill'га айлантириш → тўлов; expense; SalesReceipt;
CreditMemo → apply; VendorCredit; чет валюта invoice (курс prefill +
home жами); банк ўтказма (USD↔UZS, калькулятор билан); reconciliation
кичик оқим; inventory: кирим (bill) → adjustment акт → transfer акт →
қолдиқ/movements текшируви; payroll: run → тўлов → ведомость;
Excel import (шаблон юклаш); factory reset (тасдиқ занжири);
қидирув (/ фокус + натижага ўтиш); аудит журнали ёзувлари.

**JS компонентлар (ҳар бири алоҳида майда тестлар - икир-чикир):**
combobox: қидирув/клавиатура/quick-add модал/BR хато/динамик сатр;
мини-калькулятор: «=» ифода → боғлиқ майдонлар янгиланиши (086
регресси!); контекстли ёрдам: саҳифа ва майдон (?) ҳар икки layout'да
(079 регресси!), Esc//ташқи click; мега-меню; drawer'лар; жадвал
row-click; UoM бирлик филтри + нарх prefill; курс autofill занжири;
формада home жами жонлилиги; сатр қўшиш/ўчиришда жами (088 регресси).

**Мобил (375px)**: асосий саёҳатлардан 8-10 таси + drawer/bottom-sheet
хулқлари. **Тил smoke**: ru ва en'да биттадан кириш+invoice рўйхати.

## Қоидалар

- PostingService'га тегилмайди, ҳужжатлар фақат UI орқали - бу
  тўпламнинг бутун маъноси (server API чақириқлари ТАҚИҚ, фақат
  seed helper истисно).
- Прогон ҳисоботи: жами/ўтди/FLAKY/йиқилди + йиқилганларга trace
  йўли. Флейк белгиланганлар рўйхати ҳисобот охирида.
- Бу тўплам релиз дарвозасига КИРМАЙДИ (у тез гейтни сақлайди);
  қачон юргизиш фойдаланувчи қарори: катта тўлқин ёпилганда,
  deploy'дан олдин, катта refactor'дан кейин.
- Аралаш ёзув: тест номлари/изоҳлар мавжуд қоидада (кирилл изоҳ).
